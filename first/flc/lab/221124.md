# Building simple compilers with Bison and Flex

## Compilers

Compilers translate a program from language $L$ into a semantically equivalent
program expressed in language $L_1$. It is organized as a pipeline. Each stage
has its own purpose:

1. Front-end: converts from source language into an intermediate form. This
   intermediate form is common to all languages compilable with that compiler.
2. Middle-end: applies transformations and optimizations on the intermediate
   form
3. Back-end: converts from the intermediate form into target machine language.

### Front-end

Most of the lectures of this course will be on the front-end since all it does
is recognizing the syntax and the semantics of the program.

## ACSE

It is a simple teaching compiler that accepts a c-like source (LANCE) and emits
a RISC-like (MACE). It comes with two other helper tools forming an entire
toolchain: `asm`, for assembling MACE, and `mace`, a simulator for the
fictitious MACE processor.

### LANCE

A small subset  of C99:

- standard set of arithmetic/logic/comparison operators
- reduced set of control flow statements (while, do-while, if)
- only one scalar type (`int`)
- only one aggregate type (`int[]`)
- no functions

We have only the two following IO operations: `read(var)` and `write(var)`.

A source file is divided into two sections: variable declaration at the top and
statements after (C89-like).

The source code is tokenized by a flex-generated scanner and the stream of
tokens is parsed by a bison-generated scanner. The code is translated to a
temporary intermediate representation by the semantic actions in the parser.

There is no middle-end since no optimizations are done.

### ACSE's IR

The IR is the almost identical to the output MACE assembly language. WE have the
usual set of instructions:

1. Arithmetic and logic (`ADD`, `SUB`)
2. Memory  access instructions (`LOAD`, `STORE`)
3. Conditional and unconditional branches (`BEQ`, `BT`)
4. Special IO (`READ`, `WRITE`)

We have unlimited registers and memory locations. Registers are the variables
and are all 32-bit signed integer. The instruction decides whether the contents
of a register must be interpreted as a pointer. Immediates are constant values
encoded directly into the instruction. Labels are constant pointers used both
for conditional jumps and for pointing to the location of a statically allocated
array. The actual address is decided by the assembler.

| Type    | Operands                                         |
|:-------:|:------------------------------------------------:|
| Ternary | 1 destination and 2 sources                      |
| Binary  | 1 destination, 1 source register and 1 immediate |
| Unary   | 1 destinatino and 1 address operand              |
| Jump    | 1 address operand                                |

| Type              | Syntax                 | Meaning                                           |
|:-----------------:|:----------------------:|:-------------------------------------------------:|
| Register symbolic | `R<n>`                 | The n-th register                                 |
| Register indirect | `(R<n>)`               | Data at the addrss contained in the n-th register |
| Symbolic address  | `L<n>` or `<label id>` | The address identified by the label               |
| Immediate         | `#n`                   | Integer constant                                  |

There are two special register:

- `R0`: always 0
- `PSW` (status word): implicitly read/written by arithmetic operations,
  contains four flags: Negative, Zero, (V) overflow, and Carry

Some of the branching instructions are `BT`, `BEQ`, `BNE`. When we arrive at a
branch instruction, the PSW is checked to decide whether to branch or not.

The variable table contains the list of variables declared in the program. A
variable can be either scalar or an array: scalars have  registers where they
are stored and an initial value; arrays have a size and a label to a memory
location.
