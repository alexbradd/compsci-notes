# Laboratory session

## Bison

The file format is similar to that of flex:

```txt
%{
  Prologue
%}
Definitions
%%
Rules
%%
User code
```

Different syntactic elements can be defined (e.g tokens, operator precedence,
representation types for non-terminal symbols, language axiom). To define a
token we use

```txt
%token IF ELSE WHILE DO FOR
```

In the generated parser each token is assigned a number:

```c
enum {
  /* ... */
  IF = 258,
  ElSE = 259,
  /* ... */
}
```

### Grammar rules

Grammar rules are defined in BNF notation. If not specified, the lhs of the
first rule is the axiom

```txt
sections : sections section
         | /* empty */
         ;
section  : LSQUARE ID RSQUARE options
         ;
options  : options option
         | option
         ;
option   : ID EQUALS NUMBER
         | ID EQUALS STRING
         ;
```

### Semantic actions

Like flex, bison allows us to specify semantic actions in grammar rules. A
semantic action is conventional C code and can be specified at the end of each
rule alternative.

```txt
option : ID EQUALS NUMBER
         {
            /* code */
         }
       | ID EQUALS STRING
         {
            /* code */
         }
       ;
```

Semantic actions are executed when the rule they are associated with has been
completely recognized. A consequence is the order of execution is bottom-up
w.r.t the syntactic tree.

Semantic actions can be also put mid-rule:

```txt
section: LSQUARE ID RSQUARE { /* 1 */ } options { /* 2 */ }
```

Bison internally normalizes the grammar in order to have only end-of-rule
actions.

```txt
section: LSQUARE ID RSQUARE $@1 options { /* 2 */ }
       ;
$@1    : %empty
         { /* 1 */ }
       ;
```

### Semantic values

To keep track of what each token/non-terminal represents we use semantic values.
We associate a variable to each token or non-terminal parsed:

1. For tokens: its value is assigned in the lexer
2. For non-terminals: its value is assigned in the semantic action of that
   non-terminal

We read that variable in the rules that use that token or non terminal.

Semantic values uses some types:

1. `%union` specifies the entire collection of possible data types
2. `%token` specifies types for terminals
3. `%type` specifies type for non-terminals

```txt
%union {
  int int_val;
  const char *str_val;
  option_t option_val;
}

%token <str_val> ID
%token <str_val> STRING
%token <int_val> NUMBER
%type <option_val> option
```

The semantic value of each grammar symbol in a production is a variable called
`$i`, where `i` is the position of the symbol. `$$` corresponds to the semantic
value of the rule itself. Mid-rule actions count in the numbering and have
additional restrictions: you cannot access symbols that come later and cannot
use `$$`.

```txt
section : LSQUARE               # $1
          ID                    # $2
          RSQUARE               # $3
          { printf("%s", $2); } # $4
          options               # $5
          { $$ = create_section($2, $5); }
          ;
```

### Interface

The generated file is a C file with suffix `.tab.c` and accompanying header
file. Main parsing function is `int yyparse(void);`. For reading tokens the
parser uses the same `yylex()` function that flex-generated scanners provide.
Additionally bison defines the `yylval` global that contains the semantic value
of the last token returned by `yylex`. The type is the union of the types in
the bison source.

### Precedence and associativity

In case of an ambiguity in the grammar, we need to define a way to decide which
rule takes precedence depending on the rule:

- Some expression have higher precedence than others
- If all operators have the same precedence they may be associative

To declare precedence in bison we use `%precedence`. We list tokens in order of
growing precedence in the definition section. If two tokens have the same
precedence they are listed on the same line

```txt
%precedence PLUS MINUS
%precedence MUL DIV
```

For associativity we do the same, but we use `%left` for left-associativity,
`%right` for right associativity and `%noassoc` for no associativity.

```txt
%left PLUS MINUS
%left MUL DIV
```
