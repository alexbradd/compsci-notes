# The ACSE compiler

## Variables

Syntax for variable declaration is similar to the one in C. The semantic value
is a C string with the name of the variable (dynamically allocated). Constant
integer values have as semantic value the costant value converted with `atoi`.

Each variables declaredmust be added to the variable list. The function for
registering a variable is:

```c
void createVariable(
  t_program_infox *program,
  char *id,        // variable identifier
  int type,        // the type (always integer)
  int isArray,     // 0/1 if the var will be an array
  int arraySize,   // Number of elements of the array
  int init_val);   // Initial value (scalars only)
```

Note: this function frees the identifier string for us.

Creating a variable only tells ACSE that is exists. No space for its value is
reserved. The compiler will know its position only at runtime. This is a form
of planning.

Accessing a variable is done with the `get_symbol_location(char*, 0)` function. It
returns the integer ids of the register containing the variable. It doesn't free
the identifier for us. To assign a variable, we use:

```c
gen_addi_instruction(program, r_var REG_0, <constant>);
```

Or any other `gen_*_instruction` (there is one for each instruction).

## Expressions

Expressions appear in RHSs of assignments, array indices and conditions in
control statements. Almost all operators that are present in the C language are
supported. The precedence is the exact same as C, quirks included.

Unary minus is bugged: since it is the same token as subtraction, the same
precedence rules apply. So `-1 * 2 - 3` evaluates to `(- (1 * 2)) - 3` and not
to the natural `((-1) * 2) -3`.

To calculate complex expressions, we need registers not associated with
variables, for this we use `int getNewRegister(...)` to get a free register.
Note that this function does not generate any code, it only returns a free
register identifier doing `last_used_reg++`.

The pattern of generating code to put acostant value in a register is very
common, so we have two helper functions:

1. `gen_load_immediate()` puts a constant in anew register
2. `gen_move_immediate()` puts a constant in any register

Comparison requires more complex code sequences using the set instructions.
They come in variants like branch instructions: `SLT, SGT, SEQ, SNE, SLE, SGE`.
They implement the same logic conditions as branching, but instead of branching
they set a register to zero or one.

### Constant folding

The only optimization implemented by ACSE: expressions between constants are
calculated at compile time. To implement it, the idea is to have a double
meaning for the semantic value: we have a `t_axe_expression` struct that can
hold a `value` and an `expression_type` (either `IMMEDIATE` or `REGISTER`). The
value of `expression_type` decides whether `value` is a constant integer
(`IMMEDIATE`) or a register identifier (`REGISTER`).

To set the semantic value of an expression, we can use the `create_expression()`
helper (or set the values manually). For every operator, we need to check the
types of the two `expression_type`s and act accordingly. Fortunately there are
the `handle_bin_numeric_op()` and `handle_binary_comparison()` helper functions
that implement the boilerplate for use, we only need to pass the operands and
the operation type. Non binary operations are handled manually.

## Arrays

We left arrays behind. We need to modify our expression and assignment methods.

To access arrays, we have two helper functions that generate most code for us:
`loadArrayElement` and `storeArrayElement`:

- `loadArrayElement(program, id, index)`:
  - `char *id`: the variable identifier of the array
  - `t_axe_expression index`: constant or register. The ID with the subscript to access
- `storeArrayElement(program, id, index, data)`:
  - (previous identical to `loadArrayElement`)
  - `t_axe_expression data`: constant or register. ID with the value to put in
    the array

To check whether a variable is an array or not, we can use the `getVariable()`
function. It returns a `t_axe_variable` struct that contains all information
known about a variable:

```c
typedef struct t_axe_variable {
  int type;
  int isArray;
  int arraySize;
  int init_val;
  char *ID;
  t_axe_label *labelID;
} t_axe_variable;
```
