# The ACSE compiler

## Share variables between semantic actions

Variables defined inside semantic actions are local to said action (scopes duh).
We have mainly three ways to share a value between actions:

1. Global variables:
   - Pros: easy
   - Cons: we cannot nest save statements
2. Global stack:
   - Pros: statements are nestable
   - Cons: cumbersome to implement
3. Repurpose a symbol's semantic value as a variable: we can use unused semantic
   values to store our temporary values
   - Pros: simple to implement and works with nestable statements
   - Cons: doesn't work when the variable must be accessible from multiple rules

## Control statements

### Branches

Branching is done with the `BT <label>` instruction. Labels can be forward (we
jump forward) or backwards (we jump backwards). Since ACSE is a syntactic
directed translator we need to be able to both generate a label and later assign
it and generate a label+assign it.

Labels for branches are created using the `newLabel()` function, however it is
not inserted into code. `assignLabel()` inserts a label into the instruction
list. `assignNewLabel` combines the two previous functions.

### if statement

To store the label of the if statement, we use the semantic action of the `if`
keyword to store the value of the label. Each part of the rule generates
something:

1. `exp`: generated the boolean value
2. The following semantic action generates the branching code
3. The `code_block` generates the _then_ part of the if
4. The following action generates assigns the label after the body

If `exp`'s type is immediate, we can optimize a bit and precalculate which
branch to take at compile time. Since the condition is known at compile time, we
can use an unconditional jump and simply insert/omit the jump instruction
depending on whether the condition will be taken or not.

### while and do-while statements

For `while` we need 2 labels: one backwards and one forwards. To share data
inside the rule we use the semantic value trick with a struct containing the two
labels. Code is similar to the if one.

`do-while` has a simpler control flow graph: we need only one label and jump
back when the condition is true. The loop body also executes at least once.

## Traps in syntactic-driven translation

In syntactic-driven translation, we translate source into IR as we find it. Thus
we need to be extra careful if the relation between our CFG and grammar rule is
not direct. To work around this, we need to be crafty with our labels and jumps.
