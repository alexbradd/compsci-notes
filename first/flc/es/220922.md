# Laboratory session

## Regular expressions

Basics:

- `x`: the `x` character
- `.`: any char expect newline, `\\` escapes characters
- `[xyz]`: `x`, `y`, or `z`
- `[a-z]`: any character between `a` and `z`
- `[^a-z]`: any character except those between `a` and `z`

Composition (given two regex `R` and `S`):

- `RS` concatenation
- `R|S`: `R` or `S`
- `R*`: star operator
- `R+`: cross operator
- `R?`: zero or one occurrences
- `R{m,n}`: a number of occurrences between `n` and `m`
- `R{n,}`: a number of occurrences bigger than `n`
- `R{,m}`: at most `m` occurrences

Utilities:

- `(R)`: capturing group
- `^R`: the beginning of a line
- `R$`: the end of the line
- `\t`, `\n`: tab and newline
- `\w`, `\d`, `\s`: words, digits and whitespaces
- `\W, \D, \S`: complements of the above

## `flex`

Words are the simplest construct in a language. In a natural language, all words
can be enumerated, in an artificial one it not possible. A lexical analyzer
must:

1. Recognize tokens in a stream of characters
2. Decorate tokens with additional info

This analysis is performed through a scanner. A scanner is just a big finite
state automata.

`flex` is a tool to generate scanners based on regular expression descriptions.
The program creates a `c` source file that needs to be compiled and then can be
used.

### Specification file

A file is divided in three sections by `%%`:

1. Definitions: declare useful regex
2. Rules: binds regex to actions
3. User code: C code containing helper functions

#### Definitions

A definition associates a name to a set of characters. Regex is used o define
character sets. One addition to standard syntax: quotes can be used for literal
strings.

```txt
LETTER       [a-zA-Z_]
DIGIT        [0-9]
LETTERDIGIT {LETTER}{DIGIT}
```

#### Rules

A rule represents a full token to be recognized. Each token is described by a
regex. For each match a semantic action is defined.

```txt
{LETTER}({LETTER}|{DIGIT})*  {return 1;}
{DIGIT}+                     {return 1;}
[ \t]+                       {/* noop */}
"if"                         {return 3;}
```

The semantic actions is C code that will be executed when that token is found.
The value returned is the identifier of the token. If the code does not return
anything, the scanner simply continues evaluation.

There are two globals available for use: `char* yytext`  is the matched text and
`int yylength` is the matched text length.

Simpler applications put business logic directly inside semantic actions, while
more complex one use a separate parser and simply assign a value to the given
token and return that value.

#### User code

User C code is copied to the generated scanner as is. Useful stuff to have
includes: `main`, routines used by actions, wrappers etc.

Arbitrary code can also be put inside definitions and rules sections by wrapping
it with `%{ %}`. The code is copied as is into the generated scanners. This
method is usually used for headers and global declarations.

### Generated scanner

The generated scanner is a C file that exports:

```c
FILE *yyin = stdin;
int yylex(void);
```

The `yylex` function parses the file `yyin` until:

1. A semantic action returns.
2. The file ends (returns 0)

Flex requires us to implement only a single function: 

```c
int yywrap(void);
```

This function is called only when the file ends. It gives us the opportunity to
open other files and continue scanning. If parsing should continue, `0` should
be returned, otherwise `1`. If this function is not wanted, we can put `%option
noyywrap` in the scanner specification.

### Scanner behaviour

1. Longer matching rule: if more that one match is found, the one that is the
   longest is selected
2. First rule: If more than one string with the same length is matched, the
   rule listed first will be triggered.
3. Default action: if no rules are found, the next character in input is
   considered mathced implicitly and printed to the output stream as is.
